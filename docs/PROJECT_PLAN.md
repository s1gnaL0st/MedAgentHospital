# MedAgent-Hospital 项目规划（两周）

## 1. 项目定位

面向**医疗 Agent 研发岗**实习申请，复现并工程化论文
《Agent Hospital: A Simulacrum of Hospital with Evolvable Medical Agents》的核心机制：

- SEAL：仿真世界自动生成数据 + Agent 在仿真中进化；
- MedAgent-Zero：医学案例库（成功病例检索复用）+ 经验库（失败反思生成规则，验证后入库）。

项目的研究主线是验证三个机制：

1. 动态多 Agent 会诊是否优于单医生，并且会诊收益是否值得额外成本；
2. 案例记忆与失败反思是否提升未见仿真病例上的决策质量；
3. 规则验证、生命周期和失败回放是否带来稳定的持续改进，而非训练集记忆或错误累积。

DeepSeek API 与 HuatuoGPT-II 是后续可替换的推理后端变量，不是“医疗有效性”的证明，
也不替代多 Agent 机制对照实验。

## 2. 论文机制映射

| 论文概念 | 本项目落地 |
| --- | --- |
| Agent Hospital | 病人 / 护士 / 医生 Agent + 就诊闭环（分诊、问诊、检查、诊断、开药） |
| SEAL | 仿真数据自动生成（病人 Agent 生成器）+ 进化训练循环 |
| MedAgent-Zero | 案例库 + 经验库：检索相似病例、反思规则、验证后入库 |
| Learning curve | held-out 仿真病例上的随训练量变化曲线 |
| External sanity check | 独立医学题库只用于检查底座知识，不单独证明协作有效 |

## 3. 系统架构

```text
医学知识库（科室 / 疾病 / 症状 / 检查 / 治疗 / 鉴别要点）
        |
        v
病人 Agent 生成器 ---- 生成人口学、病史、症状、检查结果
        |                 （ground truth 对医生隐藏）
        v
护士 Agent（分诊） -> 医生 Agent（问诊 / 选检查 / 诊断 / 治疗方案）
        |                    |
        |                    +--> 案例库（成功病例，检索增强）
        |                    +--> 经验库（失败反思规则，验证保留）
        v
进化训练器：治疗 N 个病人 -> 评估（虚拟集 + MedQA 风格题）-> 学习曲线
        |
        v
Web 仪表盘（训练控制 / 交互诊断回放 / 记忆库浏览）
```

## 4. 技术栈

- Python 3.10，类型注解 + dataclass；
- LLM：统一 OpenAI 兼容接口；
  - 本地开发：DeepSeek API，key 放 `.env`（不入库）；
  - 垂类底座：3090 + vLLM 部署 HuatuoGPT-II-7B（`http://<server>:8000/v1`）；
  - 无 API 时：规则推理模式兜底，保证演示离线可跑；
- 后端：FastAPI + uvicorn；
- 前端：原生 HTML/CSS/JS 轻量仪表盘（不引入重前端框架）；
- 实验图表：matplotlib；
- 测试：pytest；
- 文档与交付：中文文档，项目发布到 GitHub。

## 5. 医学知识库范围

**重要前提：论文未公开训练数据/知识库，也未找到官方代码仓库。**
附录 A 只说明了构建方法（百度健康百科 + 丁香园常见病 + GPT-4 补充，
21 个临床科室共 339 种疾病），未提供结构化数据。因此本项目知识库全部自建。

- 科室 6 个：心内科、呼吸科、消化科、神经内科、内分泌科、皮肤科；
- 疾病 40-50 种常见病；
- 每种疾病字段：症状、危险因素、相关检查及预期结果、鉴别要点、治疗方案；
- 数据参考公开医学资料（如百度健康百科、梅奥诊所公开页面、WHO 公开材料）整理，
  仅作演示与研究，**明确标注非临床用途**；
- 病人 Agent：由 LLM 耦合知识库生成，可控制年龄 / 性别 / 病史 / 症状分布。

## 7. 评估设计

- 主要问题：在相同病例、推理后端与实验配置下，动态会诊、案例记忆和失败反思自进化
  是否提升未见病例表现；
- 初步实验：`medagent_hospital/simulacrum/experiment.py` 固定 seed 生成 train / validation /
  test，测试集只读并执行记忆签名校验；
- B0-B5 对照：单医生、案例记忆、动态会诊、动态会诊加记忆、完整自进化、固定每例会诊；
- 主要指标：诊断/分诊准确率、Top-k、会诊纠错与伤害率、平均步骤、检查数、记忆命中、
  规则存活率和失败回放恢复率；
- 外部 MedQA/CMB/CBLUE 题库只作为模型知识 sanity check，不能直接推出多 Agent 协作有效；
- 统一运行入口：

  ```powershell
  D:\python\python.exe scripts\run_initial_experiment.py
  ```

旧版底座对比矩阵保留为后续实验：

| 底座 | 进化前 | 进化后 |
| --- | --- | --- |
| DeepSeek | 虚拟集 + 选择题 | 虚拟集 + 选择题 |
| HuatuoGPT-II-7B | 虚拟集 + 选择题 | 虚拟集 + 选择题 |

- 额外指标：案例库命中率、经验规则留存率（论文改进点：规则存活可视化）。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 本地 4GB 显卡跑不动垂类模型 | 本地用 DeepSeek，HuatuoGPT 全部放 3090 |
| 知识库数据质量影响效果 | 缩小疾病范围、人工校验、标注演示用途 |
| 进化效果不明显 | 先用规则模式验证机制，再切换到 LLM |
| 两周时间紧张 | 先核心后 UI，仪表盘保证可用即可 |
